# Бонус: тест-кейс текстом → Playwright-тест

```bash
node bonus/generate.mjs bonus/cases/05-cancel-on-customer-form.txt
# або: npm run generate -- bonus/cases/05-cancel-on-customer-form.txt
# інша модель: GEN_MODEL=<id> node bonus/generate.mjs <кейс>
```

## Як працює

1. [generate.mjs](generate.mjs) читає тест-кейс із файлу (назва, кроки, очікуваний результат).
2. Збирає промпт: правила проєкту з [CLAUDE.md](../CLAUDE.md), page objects, фікстури, тестові дані, маршрути і
   один готовий spec як зразок стилю. Модель має **використати наші шари**; якщо потрібного методу немає —
   написати про це коментар, а не підставити сирий локатор.
3. Модель: **Claude Code у headless-режимі** (`claude -p`), ключ API не потрібен; `GEN_MODEL` задає модель.
   Якщо задано `ANTHROPIC_API_KEY`, скрипт іде напряму в Anthropic Messages API. Обидва шляхи є в коді,
   приклади нижче зроблені через `claude -p`.
4. **Запобіжники**, через які відповідь має пройти, перш ніж потрапить у тести:
   - у відповіді є блок ```` ```ts ```` (текст замість коду не зберігається як spec);
   - у spec немає сирих селекторів і пауз (`getBy*`, `locator()`, `$()`, `waitForTimeout`, `xpath=`, `css=`);
   - проєкт проходить перевірку типів разом із цим spec;
   - Playwright запускає його: хоча б один тест пройшов, жодного пропущеного, впалого чи нестабільного.
5. Spec спершу пишеться як `tests/ui/generated/<кейс>.candidate.spec.ts`. Лише якщо всі перевірки пройдено **і**
   переглянутого spec з такою назвою ще немає, він стає `<кейс>.spec.ts`. Переглянутий тест скрипт не
   перезаписує; кандидат, що не пройшов, прибирається з `tests/`.
6. Усе для рев'ю лишається в `bonus/examples/<кейс>/`: `input.txt`, `generated.spec.ts` (**сирий** вивід моделі),
   `run.log`, `result.json` (модель, час, результат кожної перевірки).

`tests/ui/generated/` — уже **переглянуті** тести, які входять у звичайний прогін і CI. Ручні правки в них
позначені коментарями `hand fix` (правка за результатом мого рев'ю) і `review fix` (за зауваженням рев'юера).

## Висновки

- З контекстом проєкту модель пише тести в стилі репозиторію і без сирих локаторів. Без правок, які
  стосуються логіки, пройшли 01, 03 і 05; 02 пройшов, але порушив правило про тестові дані.
- Коли потрібної дії немає, модель не вигадує селектор, а пропускає тест і пише, чого бракує (04, 06).
  Конвеєр має **не рахувати такий тест успішним** — перша версія рахувала, поточна відхиляє.
- Згенероване все одно треба читати: ручні правки були не про «тест падає», а про «тест проходить, але
  порушує правила проєкту».
