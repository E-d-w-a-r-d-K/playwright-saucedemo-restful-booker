# QA test task: saucedemo UI + restful-booker API

Автотести на **Playwright + TypeScript**:
- UI — https://www.saucedemo.com (користувач `standard_user`);
- API — https://restful-booker.herokuapp.com.

Тести запускаються в GitHub Actions на кожен push; HTML-звіт зберігається як артефакт.
Як агент допомагав і де помилявся — у [AI_WORKLOG.md](AI_WORKLOG.md), правила для агента — у [CLAUDE.md](CLAUDE.md).

## Як запустити

Потрібен Node.js 20+.

```bash
npm ci
npx playwright install chromium
npm test              # усі тести (UI + API)
npm run test:ui       # лише UI
npm run test:api      # лише API
npm run typecheck     # перевірка типів
npm run report        # відкрити HTML-звіт останнього запуску
```

У CI: вкладка **Actions** → запуск → артефакт **playwright-report** (HTML-звіт) і **test-results**
(JUnit XML, трейси й скріншоти тих тестів, що впали).

## Що покрито

**UI (19 тестів + 3 на відомі баги)**

| Сценарій | Що саме перевіряється |
|---|---|
| Логін | вхід `standard_user` → сторінка Products і всі 6 товарів; вихід через меню закриває доступ до `/inventory.html` |
| Каталог | повний список назв і цін (6 товарів); сторінка товару показує ту саму назву, ціну й опис, що й картка |
| Сортування | усі 4 варіанти (A→Z, Z→A, ціна ↑, ціна ↓): порядок **усього** списку порівнюється з відсортованим каталогом |
| Кошик | лічильник 1 → 2; у кошику саме ці товари з цінами; видалення оновлює кошик і лічильник; кошик зберігається після перезавантаження |
| Чекаут | 2 товари: Item total = сума цін, Tax = 8%, Total = Item total + Tax; замовлення завершується, кошик порожніє |
| Негативні | неправильний пароль; `locked_out_user`; порожня форма логіну; `/inventory.html` без входу; порожні ім'я / прізвище / індекс у чекауті (кожне поле окремо, точний текст помилки) |

**API (4 тести + 6 на відомі баги)**

| Сценарій | Що саме перевіряється |
|---|---|
| Флоу | auth → токен; create → id і тіло дорівнює надісланому; get → те саме; update з токеном → нові дані в GET; delete → успіх; get → 404 |
| Негативні | update без токена → 403, бронювання не змінилось; update і delete з підробленим токеном → 403, бронювання на місці; неіснуючий id → 404 |

Кожен тест незалежний: свій вхід, свої дані. API-тести створюють бронювання з унікальним прізвищем і видаляють
їх після себе — пісочниця спільна для всіх, хто її тестує.

**Відомі баги** оформлені як тести на **правильну** поведінку з `test.fail()`: поки баг є, тест «очікувано падає»
і набір лишається зеленим; щойно баг виправлять — тест стане червоним («unexpectedly passed»), і позначку треба зняти.
Для кожного такого тесту перевірено, що він падає саме на перевірці бага, а не на локаторі.

## Що свідомо не покрито

- **Інші користувачі saucedemo** (`problem_user`, `performance_glitch_user`, `error_user`, `visual_user`) — завдання про `standard_user`; це наступний крок.
- **Інші браузери й мобільний вигляд** — лише Chromium, щоб CI був швидким.
- **Візуальні порівняння, доступність, продуктивність.**
- **API:** `PATCH /booking/{id}`, фільтри `GET /booking?firstname=…`, `GET /ping`, авторизація через Basic Auth.
- **Сторінки всіх 6 товарів** — перевірена одна сторінка товару; решта мають ту саму розмітку.
- `restful-booker` — публічна пісочниця на Heroku, яка іноді відповідає 503; у CI стоїть 1 повтор саме через це, локально повторів немає.

## Знайдені баги

### BUG-UI-1. Замовлення оформлюється з порожнім кошиком
- **Середовище:** saucedemo.com, `standard_user`, Chrome.
- **Кроки:** 1) увійти; 2) не додаючи товарів, відкрити кошик; 3) Checkout; 4) заповнити ім'я, прізвище, індекс → Continue; 5) Finish.
- **Очікувано:** з порожнім кошиком кнопка Checkout неактивна або показує помилку; замовлення не створюється.
- **Фактично:** відкривається підсумок «Item total: $0 / Total: $0.00», після Finish — «Thank you for your order!».
- **Тест:** `tests/ui/known-bugs.spec.ts` → BUG-UI-1.

### BUG-UI-2. Форма чекауту приймає поля з самих пробілів
- **Кроки:** 1) увійти, додати будь-який товар; 2) кошик → Checkout; 3) у First Name, Last Name, Zip/Postal Code ввести по три пробіли → Continue.
- **Очікувано:** помилка «First Name is required» (поле без символів, крім пробілів, вважається порожнім).
- **Фактично:** відкривається крок підсумку замовлення (`checkout-step-two.html`).
- **Тест:** BUG-UI-2.

### BUG-UI-3. Reset App State не скидає кнопки товарів
- **Кроки:** 1) увійти; 2) додати «Sauce Labs Onesie» — кнопка стає «Remove», лічильник 1; 3) меню → Reset App State.
- **Очікувано:** лічильник зникає, кнопка товару знову «Add to cart».
- **Фактично:** лічильник зникає, але кнопка лишається «Remove» до перезавантаження сторінки — інтерфейс не відповідає стану кошика.
- **Тест:** BUG-UI-3.

### BUG-API-1. Неправильні облікові дані → 200 OK
- **Запит:** `POST /auth` з `{"username":"admin","password":"wrong"}`.
- **Очікувано:** `401 Unauthorized`.
- **Фактично:** `200 OK`, тіло `{"reason":"Bad credentials"}` — клієнт, що перевіряє лише статус, вважатиме вхід успішним.

### BUG-API-2. Бронювання без обов'язкових полів → 500
- **Запит:** `POST /booking` з `{"firstname":"OnlyName"}`.
- **Очікувано:** `400 Bad Request` з описом відсутніх полів.
- **Фактично:** `500 Internal Server Error`.

### BUG-API-3. DELETE відповідає 201 Created
- **Запит:** `DELETE /booking/{id}` з валідним токеном.
- **Очікувано:** `200 OK` або `204 No Content`.
- **Фактично:** `201 Created`, хоча нічого не створено.

### BUG-API-4. Повторне видалення → 405
- **Кроки:** видалити бронювання; повторити `DELETE /booking/{id}` з тим самим id.
- **Очікувано:** `404 Not Found`.
- **Фактично:** `405 Method Not Allowed`.

### BUG-API-5. Виїзд раніше за заїзд приймається
- **Запит:** `POST /booking` з `"bookingdates": {"checkin":"2027-01-15","checkout":"2027-01-10"}`.
- **Очікувано:** `400 Bad Request`.
- **Фактично:** `200 OK`, бронювання створене з некоректними датами.

### BUG-API-6. Нечислова ціна зберігається як null
- **Запит:** `POST /booking` з `"totalprice": "abc"`.
- **Очікувано:** `400 Bad Request`.
- **Фактично:** `200 OK`, у збереженому бронюванні `"totalprice": null`.

Також помічено, але не винесено в тести: від'ємна ціна (`"totalprice": -5`) приймається з `200 OK`.
